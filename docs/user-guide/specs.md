# Declarative environment specs

{py:mod}`openswmm_gymnasium.spec` builds any env from plain JSON: the env
type, the model, the action factories, the observation features, the reward
terms and the wrappers. It is what the openswmm.mcp gym tools use, and it
suits configs kept in files or generated by a program. It needs the `spec`
extra, which adds pydantic:

```bash
pip install "openswmm.gymnasium[spec]"
```

## Build an env

```python
from openswmm_gymnasium.spec import EnvConfig, build_env

config = EnvConfig.model_validate({
    "env_type": "rtc",
    "inp_path": "twin_tank.inp",
    "runtime_factories": [
        {"kind": "orifice_setting", "params": {"link_ids": ["ORIF"]}},
        {"kind": "field_setpoint",
         "params": {"path": "node.lateral_inflow", "ids": ["T1"], "low": 0.0, "high": 5.0}},
    ],
    "observations": {
        "node_depths": ["T1", "T2"],
        "fields": {"link.stats.max_filling": ["OUT"]},
        "include_clock": True,
    },
    "reward_terms": [{"kind": "flooding_volume", "params": {}}],
    "control_interval_steps": 4,
    "max_episode_steps": 50,
})
env = build_env(config)
obs, info = env.reset()
info["observation_units"]   # ['ft', 'ft', 'fraction', 'dimensionless', ...]
```

`env_type` is one of `rtc`, `cip`, `joint`, `mo_rtc`, `control_curve`,
`market` and `schedule`; each type checks that the fields it needs are
present. `observations` is described in {doc}`observations`, including the
catalog `fields` and the 2D `cell_fields`. `EnvConfig.model_json_schema()`
returns the full schema.

## Kinds and their parameters

Every factory, reward term, policy factory and wrapper is named by a `kind`
with a validated `params` object. The registry lists them with their
parameter schemas:

```python
from openswmm_gymnasium.spec import get_kind, list_kinds

[k.kind for k in list_kinds("runtime_factory")]
# ['field_setpoint', 'heat_source_temperature_setpoint', 'node_lateral_inflow', 'orifice_setting']
get_kind("runtime_factory", "field_setpoint").params_model.model_json_schema()
```

The categories are `design_factory`, `runtime_factory`, `reward_term`,
`policy_factory` and `wrapper`.

## Run an episode

`run_episode(config, policy, run_dir)` runs one episode under a declarative
policy and writes `trajectory.jsonl` and `summary.json` into `run_dir`:

```python
from openswmm_gymnasium.spec import run_episode

summary = run_episode(
    config,
    {"kind": "constant", "action": {"runtime": {"orifice_setting": [1.0]}}},
    "runs/constant",
)
summary["reward_components_total"]
```

A policy is `{"kind": "constant", "action": {...}}`, `{"kind": "random",
"seed": 7}` or `{"kind": "replay", "actions": [...]}`. For interactive use,
{py:class}`~openswmm_gymnasium.spec.envs.EnvManager` keeps named envs open
with a capacity cap and an idle sweep.

## Errors

A config that does not match the schema raises pydantic's `ValidationError`.
An unknown kind, invalid kind parameters, an unknown field path or a missing
optional dependency raise {py:class}`~openswmm_gymnasium.spec.errors.SpecError`,
whose `code` is an
{py:class}`~openswmm_gymnasium.spec.errors.ErrorCode` (`VALIDATION_ERROR`,
`DEPENDENCY_MISSING`, `ENGINE_ERROR`, ...) and whose message starts with it:

```python
from openswmm_gymnasium.spec import SpecError

try:
    build_env(config)
except SpecError as exc:
    print(exc.code, exc)
```
